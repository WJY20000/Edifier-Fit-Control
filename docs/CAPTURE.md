# 抓包手册

**Fit900NB Turbo 已经抓完并写进代码了**（2026-11-08，固件 1.0.3），结论在
[`PROTOCOL.md`](PROTOCOL.md)，代码里只有这一套命令（0.8.8 起不再有型号档案）。

这份文档现在有两个用途：

1. 想自己复核一遍：按下面的「方式一」把确认过的命令发一次，看回包对不对；
2. 固件升级后某项失效：按「方式二」抓官方 App 的完整命令流，我来对齐字节。

---

## 已确认命令（Fit900NB Turbo，固件 1.0.3）

帧格式 `AA EC cmd lenHi lenLo payload... sum8`，`sum8 = 前面所有字节之和 & 0xFF`。
十六进制直接粘进 nRF Connect 的写入框（**Write without response** 也可以）。

| # | 目的 | 粘贴这一行 | 期望回包 |
| --- | --- | --- | --- |
| 1 | 电量 | `AA EC D0 00 00 66` | `BB EC D0 00 01 2D …`（`2D` = 45%） |
| 2 | 读名称 | `AA EC C9 00 00 5F` | 尾段是 ASCII `EDIFIER Fit900NB Turbo` |
| 3 | 读固件 | `AA EC C6 00 00 5C` | `01 00 03` = 1.0.3 |
| 4 | 读降噪 | `AA EC CC 00 00 62` | `BB EC CC 00 02 2F xx`，`xx` 见下表 |
| 5 | 读场景 | `AA EC 08 00 00 9E` | `BB EC 08 00 02 00 06`（`00` 音乐 / `01` 游戏 / `02` 空间音效） |
| 6 | 读音效 | `AA EC D5 00 00 6B` | 单字节；非音乐场景回 `FF` |
| 7 | 读 LDAC | `AA EC 91 00 00 27` | `BB EC 91 00 02 11 xx`（`00` 关 / `01` 44.1&48k / `02` 96k） |

降噪 `xx`：

| 值 | 含义 | 切换到它的写命令 |
| --- | --- | --- |
| 1 | 深度降噪 | `AA EC C1 00 02 2F 01 89` |
| 2 | 舒适 | `AA EC C1 00 02 2F 02 8A` |
| 3 | 防风噪 | `AA EC C1 00 02 2F 03 8B` |
| 4 | 环境声 | `AA EC C1 00 03 2F 04 02 8F`（`02`=平衡，`01`=突出人声，`03`=突出背景声） |
| 5 | 关闭 | `AA EC C1 00 02 2F 05 8D` |

`0xCC` 只回 `[2F, 模式]`，不带环境声等级；发 `AA EC C1 00 02 2F 04 8C`（不带等级）
会回 `[2F 04 当前等级]`，这是官方 App 读等级的办法。

其余写命令：

| 目的 | 命令 |
| --- | --- |
| 场景 · 游戏 | `AA EC 09 00 01 01 A1` |
| 场景 · 空间音效 | `AA EC 09 00 01 02 A2` |
| 场景 · 音乐 | `AA EC 09 00 01 00 A0` |
| 音效（示例：低音增强=3） | `AA EC C4 00 01 03 5E` |
| LDAC 96k | `AA EC 92 00 02 11 02 3D` |
| LDAC 44.1&48k | `AA EC 92 00 02 11 01 3C` |
| LDAC 关 | `AA EC 92 00 02 11 00 3B` |

### 步骤

1. 应用商店装 **nRF Connect for Mobile**（Nordic 官方，免费）。安卓 / iPhone 都有。
2. 先关掉官方「EDIFIER Connect」，一台耳机同时只允许一个 App 连着。
3. nRF Connect → **SCAN** → 找到 `EDIFIER Fit900NB Turbo` → **CONNECT**。
4. 找到两条特征值（认开头结尾）：
   - `48090001-...-d663bd873d93` — **notify**，点右侧三个箭头订阅，图标常亮；
   - `48090002-...-d663bd873d93` — **write**，点向上箭头 → **Write** 或 **Write without response**。
5. 把上表的命令逐条粘进去，**每条之间停 1 秒**，蓝色回包会出现在 `...0001` 下面。

> 找不到 `4809...` 开头的服务、或写入报 `not permitted`：先回系统设置里把耳机
> **配对**（不是连接）再试；还不行就截图发我。

## 换了新固件时

应用只按 Fit900NB Turbo 这一套协议发命令（降噪槽位 `0x2F`）。如果固件升级后某项失效，
最省事的办法是抓官方 App 的完整命令流，对一遍字节——不要按型号去猜槽位，
同一家的不同型号会用 `0x1B` / `0x10` / `0x17`，猜必错。

### 方式二：Android HCI 抓包

> 只有安卓能做（iPhone 不给第三方取 HCI 日志）。用 iPhone 就只能做上面的手动探测。

#### A. 打开蓝牙日志

1. 设置 → 关于手机 → 连点 **版本号** 7 次，打开开发者选项。
2. 开发者选项里找到 **启用蓝牙 HCI 侦听日志**（不同品牌文案不同：
   `蓝牙 HCI 信息收集日志` / `Enable Bluetooth HCI snoop log`）→ 打开。
3. **把蓝牙关掉再打开**（必须，否则日志不会重新开始写）。

#### B. 按脚本操作官方 App

打开 EDIFIER Connect，连上耳机，然后**按顺序**做，每个动作之间停 3 秒：

1. 停在首页 10 秒（读电量 / 信息）
2. 降噪：深度 → 舒适 → 防风 → 环境声 → 关闭（每档 5 秒）
3. 环境声档位：突出人声 → 平衡 → 突出背景声
4. 场景：音乐 → 游戏 → 空间音效 → 音乐
5. 音效：把六个预设各点一次
6. LDAC：96k → 44.1&48k → 关 → 96k（会重连，等它恢复）
7. 结束前在设置里点一次「设备信息」

> 官方 App 里没有的功能跳过就行。**顺序照做**，对齐字节靠的就是顺序。

#### C. 导出日志

**没有电脑：** 开发者选项 → **生成错误报告**（Take bug report）→ **完整报告** →
完成后点分享 → 存到 Google Drive → 把链接发我。

**有电脑（更快、文件更小）：**

```bash
adb bugreport cap
# 解压 cap.zip，找下列之一：
#   FS/data/misc/bluetooth/logs/btsnoop_hci.log
#   FS/data/misc/bluetooth/bthci/*.cfa
#   FS/data/misc/bluedroid/btsnoop_hci.log
```

文件通常几百 KB 到几 MB，直接发。**太大传不动**时先在本地解码：

```bash
python3 tool/decode_btsnoop.py btsnoop_hci.log > edifier-trace.txt
python3 tool/decode_btsnoop.py BT_HCI_2026_1108_142340.cfa.curf --from 14:29:30 --to 14:33:57
```

输出的文本只有几十 KB，发这个就行。解码器不解 L2CAP/ATT（各家 snoop 封装不一致），
而是按方向拼字节流、用帧校验和切帧，所以 `.cfa` / `.log`、明文 / 异或都能吃。

## 我会怎么用这些数据

1. 把命中的槽位和「模式 → 数值」写进 `models.dart` / `opcodes.dart`（只维护这一套）；
2. 用真实回包补单元测试（`test/frame_test.dart` 里的字节断言就是这么来的）；
3. 发现新命令字（自定义 EQ、双设备连接等）就追加到 `opcodes.dart` 再放控件；
4. 重新打包源码，Actions 直接出新 APK。

## 隐私

抓包文件里有耳机的 MAC 地址和蓝牙名称。**发之前可以把 MAC 改掉**（任何 6 组十六进制
都行，改完不用管校验，那是 HCI 层之外的），或者直接发原始文件、我处理完删掉。
日志里不会有音频、位置或账号信息。
